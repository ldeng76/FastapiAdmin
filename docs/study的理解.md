# 影像检查中 Study 详解

> 本文档基于实际 DICOM 路径，详细解析影像检查中 "Study" 的含义与层级结构。

---

## 一、影像检查中 Study 的基本含义

在医学影像学中，**"Study"** 是一个非常重要的专业术语，中文通常翻译为 **"检查"** 或 **"检查项目"**，但它的具体含义比中文的"检查"更精确。

### 1.1 基本概念

**Study 指一次完整的影像检查**，包括从检查申请到图像采集、最终生成报告的全过程。

**示例：**
- 胸部 CT 检查 → 一个 **CT Study**
- 头颅 MRI 平扫 → 一个 **MR Study**
- 腹部超声检查 → 一个 **US Study**

### 1.2 Study 的层级结构（PACS / DICOM 系统）

```
Patient（患者）
  └── Study（检查）         ← 一个患者可以有多次 Study
        └── Series（序列）  ← 一个 Study 包含多个 Series
              └── Image（图像）  ← 一个 Series 包含多张图像
```

### 1.3 具体例子：头颅 MRI Study

| Study（检查）   | Series（序列）       |
| --------------- | -------------------- |
| 头颅 MRI 平扫   | T1WI 横断面          |
|                 | T2WI 横断面          |
|                 | FLAIR 横断面         |
|                 | DWI 横断面           |
|                 | T2WI 矢状面          |

### 1.4 不同语境下的含义

| 语境              | 含义                                       |
| ----------------- | ------------------------------------------ |
| 检查申请单        | Study = 检查项目（如"胸部 CT 平扫+增强"） |
| PACS 系统         | Study = 一次完整的影像数据集               |
| 影像报告          | Study = 本次检查（如"本次 Study 显示……"） |
| 科研语境          | Study = 研究                               |

### 1.5 与相似概念的区别

| 术语          | 含义                                |
| ------------- | ----------------------------------- |
| **Study**     | 一次完整的检查                      |
| Examination   | 检查过程（有时与 Study 互换使用）   |
| Series        | 序列（Study 的子集）                |
| Scan          | 单次扫描动作                        |

### 1.6 总结

简单来说，在影像检查中，**Study = 一次完整的影像检查**。一个 Study 包含针对患者某一部位、某一检查目的的所有序列和图像，是影像科医师进行诊断的基本单位。

## 二、实际 DICOM 路径解析

### 2.1 示例路径

```

1.3.46.670589.33.1.63771733385743574400001.5099219290356126080/    ← Series（序列）
```

### 2.2 路径结构总览

```
/data/wlx/DATABASE/07_disk/DCM_part07.zip_folder/
├── 11563976/                                                            ← ① Patient
│   └── 1.2.840.113564.35201818813822.17808.637716395276303393.911/     ← ② Study
│       └── 1.3.46.670589.33.1.63771733385743574400001.5099219290356126080/  ← ③ Series
│           └── *.dcm                                                     ← ④ Instance
```

### 2.3 逐层详细解释

#### ① 第一层：Patient ID = `11563976`

```
📁 11563976/
```

- **含义**：患者的唯一标识号
- 这是患者在医院的 ID（也可能是匿名化处理后的编号）
- 一个患者可以有多次检查（多个 Study 文件夹）

#### ② 第二层：Study Instance UID ⭐

```
📁 1.2.840.113564.35201818813822.17808.637716395276303393.911/
```

| 部分                                                       | 含义                                              |
| ---------------------------------------------------------- | ------------------------------------------------- |
| `1.2.840.113564`                                          | **OID 前缀** —— 这是 **GE Healthcare** 的公司标识 |
| `.35201818813822.17808.637716395276303393.911`             | 时间戳和唯一序列号                                |

**⭐ 这就是 Study！**

- 标识一次完整的影像检查
- 这个 Study 由 **GE 设备**生成
- 时间戳 `637716395276303393` 是 Unix 时间戳
- 同一个 Study 下可以包含多个序列（Series）

#### ③ 第三层：Series Instance UID

```
📁 1.3.46.670589.33.1.63771733385743574400001.5099219290356126080/
```

| 部分                              | 含义                                            |
| --------------------------------- | ----------------------------------------------- |
| `1.3.46.670589.33.1`              | **OID 前缀** —— 这是 **Philips** 的公司标识     |
| 后半段                            | 该序列的唯一标识                                |

- **含义**：一个具体的成像序列
- 这个序列由 **Philips 设备**生成
- 一个 Study 通常包含多个 Series（如 T1、T2、DWI 等）

#### ④ 第四层：图像文件

```
📄 *.dcm
```

- 每个 `.dcm` 文件就是一张 DICOM 图像
- 包含像素数据 + 患者信息 + 采集参数等元数据
- 一个 Series 通常包含几十到几百张图像

### 2.4 时间戳解析

```
Study UID 中:  637716395276303393
Series UID 中: 637717333857435744
```

转换为日期时间：
- Study 时间戳：`2022-05-25` 左右（Study 采集时间）
- Series 时间戳：`2022-05-25` 稍晚（Series 重建/后处理时间）

> 💡 这两个时间戳相差约 **2 小时**，可能是检查后医生对图像进行了重建或后处理。

### 2.5 完整层级关系图

```
Patient: 11563976 👤
│
├── Study: 1.2.840.113564...3911  🏥 (GE 设备采集的一次完整检查)
│   │
│   ├── Series: 1.3.46.670589...126080 📊 (Philips 生成的某个序列)
│   │   ├── Image_001.dcm 🖼️
│   │   ├── Image_002.dcm 🖼️
│   │   └── ...
│   │
│   ├── Series: (可能还有其他序列)
│   └── ...
```

### 2.6 关键要点总结

| 层级       | 文件夹名                              | DICOM 标识符          | 含义                       |
| ---------- | ------------------------------------- | --------------------- | -------------------------- |
| Patient    | `11563976`                            | Patient ID            | 患者                       |
| **Study**  | **`1.2.840.113564...3911`**           | **Study Instance UID** | **⭐ 一次完整检查**         |
| Series     | `1.3.46.670589...126080`              | Series Instance UID   | 一个成像序列               |
| Image      | `*.dcm`                               | SOP Instance UID      | 单张图像                   |

### 2.7 推测这次 Study 是什么

从路径信息推测：
- 由 **GE** 设备采集的某次影像检查
- 经过 **Philips** 系统进行后处理或重建
- 时间约为 **2022 年 5 月**
- 具体是 CT、MRI 还是其他，需要打开 DICOM 文件查看 `(0008,0060) Modality` 标签才能确认
