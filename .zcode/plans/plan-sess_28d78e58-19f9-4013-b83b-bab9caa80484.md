# 新桥医院 ETL-1 实现计划

## 背景与上下文

新桥医院(陆军军医大学新桥医院)原始数据位于 `docs/demodata/01_disk_字段与原始数据_2新桥/`,共 **12 个 CSV / ~135 MB**,分两个子目录:

| 子目录 | 文件数 | 行宽 | 内容 |
|---|---|---|---|
| `1_5万例排除术后_单一影像号_已处理/` | 6 | **17 列** | 纯 CT 报告 |
| `2_5万例时序影像_带病理_新_待处理/` | 6 | **30 列** | CT + 病理(LEFT JOIN 风格,病理段可空) |

抽样(LINE 2/3)确认:
- `检查报告.患者ID` = 真实 8 位数字(`07116569` / `10802887`),**HMAC 输入可用**
- 姓名 + 身份证号 = `***`(已是脱敏态)
- 日期格式 **两批不一致**: 子目录 1 用 `1956/1/17 0:00`(斜杠);子目录 2 用 `1971-09-12 00:00:00`(横杠)
- **病理段多值字段逗号分隔**: `病理.送检时间 = "2025-03-08 08:45:42,2025-03-08 08:46:30"` —— 用户决定保留原始 CSV 行粒度,由 ETL-2 处理
- 检查类别 = `CT`(半角,不像珠江的全角 `ＣＴ`)
- 无 DICOM 目录,无 README,无字段说明文件

## 已锁定的决策(经用户确认)

1. **患者 ID 策略**: HMAC 输入 = `检查报告.患者ID`(真实数字 ID),遵循 ADR-0001 由 ETL-2 派生 `ANON_` / `PT_`。
2. **CSV 物理组织**: 每子目录 = 一个 SheetSpec 输入源(`_SUB_1_IMAGING_ONLY` + `_SUB_2_IMAGING_PATHOLOGY`)。
3. **Reader 实现**: 独立 `CsvReader` 类(走 DuckDB `read_csv_auto`),`core.py:run_etl1` 按 `center.source_kind` 分流。
4. **产出范围**: 3 张表 = `patient` + `nodule_imaging` + `pathology_specimen`(对齐 zhujiang)。
5. **病理粒度**: 原始 CSV 行 = 一份病理报告,**多值字段原样入 parquet**,由 ETL-2 用 `string_split` + `UNNEST` 拆开。

## 实施步骤

### 步骤 1: 新增 `backend/app/plugin/module_medical/hospital/etl1/csv_reader.py`

新建独立 CsvReader,**优先走 DuckDB `read_csv_auto`**(用户明确要求)。类签名与 `ExcelReader` 完全对齐(duck-typed):

```python
@dataclass(frozen=True)
class SheetView:
    view_name: str
    headers: list[str]
    sheet_name: str  # 对 CSV: 用目录名(如 "1_5万例排除术后_单一影像号_已处理")

class CsvReader:
    def __init__(self, csv_dir: str | Path, memory_limit: str = "4GB"):
        # csv_dir 是子目录路径,内部 glob *.csv 并 union
        # 校验: 必须是已存在目录; 必须至少含一个 .csv
    @property
    def con(self) -> duckdb.DuckDBPyConnection: ...
    def ensure_loaded(self) -> None:
        # 无需 INSTALL/LOAD 扩展:DuckDB 原生支持 CSV
    def read_sheet(self, sheet_name: str) -> SheetView:
        # 1. 用 sha256(sheet_name)[:16] + 计数器生成唯一 view 名
        # 2. CREATE OR REPLACE TEMP VIEW <view> AS
        #      SELECT * FROM read_csv('<csv_dir>/*.csv',
        #                              all_varchar=true, header=true,
        #                              ignore_errors=true, union_by_name=true)
        # 注: union_by_name=true 兼容 6 个 CSV 表头顺序可能不一致
        # 3. SELECT * FROM <view> LIMIT 0 → 读 headers
    def close(self) -> None: ...
```

**关键 DuckDB CSV 参数**:
- `read_csv_auto` 在数据量 < 1 GB 时表现良好;新桥全量 135 MB,稳妥。
- `union_by_name=true` 解决子目录 1/2 内部 6 个 CSV 表头列序差异(虽然理论上同子目录表头一致,但防御性开启)。
- `sample_size=-1` 让 DuckDB 扫全部行再做类型推断(避免前 N 行导致日期格式误判)。
- 不做并行:`threads=1`(简单可控)。

### 步骤 4: 新增 `backend/app/plugin/module_medical/hospital/etl1/centers/xinqiao.py`

注册 code=`xinqiao`, display_name=`陆军军医大学新桥医院`, source_kind=`csv`。

**派生 3 个 SheetSpec**(对齐 zhujiang):

#### `_SUB_1_IMAGING_ONLY` (sheet_name=`1_5万例排除术后_单一影像号_已处理`)
仅子目录 1(17 列,无病理段)。产出:
- `_PATIENT_FROM_SUB1`: `DISTINCT ON 检查报告.患者ID`
- `_NODULE_IMAGING_FROM_SUB1`: `WHERE 检查报告.检查类别='CT' AND 检查报告.检查结论 ILIKE '%肺%' OR 检查报告.检查结论 ILIKE '%结节%'`

#### `_SUB_2_IMAGING_PATHOLOGY` (sheet_name=`2_5万例时序影像_带病理_新_待处理`)
子目录 2(30 列,含病理段)。产出:
- `_PATIENT_FROM_SUB2`: `DISTINCT ON 检查报告.患者ID` —— **冗余但必要**(子目录 1 缺病人,子目录 2 可能补足;`run_etl1` 会按顺序处理两份 patient,后者 DISTINCT 合并;或注册为 `derived_tables` 走 cross-source UNION)。
- `_NODULE_IMAGING_FROM_SUB2`: 同 SUB1 的 WHERE
- `_PATHOLOGY_SPECIMEN_FROM_SUB2`: `WHERE 病理.病理系统编号 IS NOT NULL`;粒度 = 原始 CSV 行;**多值字段原样入**

**核心字段映射表**:

| 源 CSV 列(中文带点号) | 目标列 | 类型 | SheetSpec |
|---|---|---|---|
| `检查报告.患者ID` | `patient_id` | str required | patient / nodule_imaging / pathology_specimen |
| `检查报告.性别` | `gender` | str | patient |
| `检查报告.报告中图像编号` | `exam_id` | str required | nodule_imaging |
| `检查报告.检查日期时间` | `exam_date` | date | nodule_imaging |
| `检查报告.检查所见` | `findings` | text | nodule_imaging |
| `检查报告.检查结论` | `impression` | text | nodule_imaging |
| `病理.病理系统编号` | `specimen_id` | str required | pathology_specimen |
| `病理.送检时间` | `specimen_received_at` | text(原始逗号串) | pathology_specimen |
| `病理.报告时间` | `report_released_at` | text(原始逗号串) | pathology_specimen |
| `病理.送检部位` | `sampling_site` | text | pathology_specimen |
| `病理.病理所见-肉眼所见` | `gross_findings` | text | pathology_specimen |
| `病理.病理所见-镜下所见` | `microscopic_findings` | text | pathology_specimen |
| `病理.病理诊断` | `pathology_diagnosis` | text | pathology_specimen |
| `病理.报告状态` | `report_status` | text | pathology_specimen |

**日期归一化策略**(用户没明确答复,我按"两批格式共存 → 各自 SheetSpec 走自己的 view"处理):
- 子目录 1 的 view 在 CsvReader 内 **预先 TRY_CAST** `检查报告.检查日期时间 AS DATE`(斜杠格式 duckdb auto_detect 多数会识别为 TIMESTAMP,失败时 `try_strptime(检查报告.检查日期时间, ['%Y/%m/%d %H:%M:%S', '%Y-%m-%d %H:%M:%S'])`)。
- 子目录 2 同理,但格式串用 `%Y-%m-%d %H:%M:%S`。
- 在 CsvReader.read_sheet 内部对**日期/时间列不预先转**,仍按 all_varchar 返回,**让 `cast_expr_for_type` 在 ETL-1 SELECT 阶段做转换**。这样 SheetSpec 的 `col_date("检查报告.检查日期时间", "exam_date")` 会自动触发 cast,走 duckdb 的 TRY_CAST,失败的置 NULL + log warning。

**`patient` 表去重策略**:
- 两个子目录的 `_PATIENT_FROM_SUB*` 走同一 `target_table="patient"`、`dedup_key=["patient_id"]`,`run_etl1` 会按顺序处理,后者覆盖前者。
- 因为两者产出的 patient schema 完全相同(都是 `patient_id + gender`),无字段冲突。
- 如需明确"两源 UNION",可注册为 `derived_tables`(类似 shengyi 的 visit_recovery),但当前 3 个 SheetSpec 顺序写入已足够。

## 风险与边界

1. **不改 ETL-2 / 不改 schema**: 本任务严格止于 ETL-1,parquet 写出即可。ETL-2 落库到 `med_*` 表的逻辑由后续 plan 覆盖。
2. **DuckDB `read_csv` 不支持中文字符串转义字面量拼接**: `CsvReader.read_sheet` 内部已用 sha256 hash + view 计数器,与 ExcelReader 一致;目录路径走 `Path(...).as_posix()`,转义单引号(`replace("'", "''")`)。
3. **6 个 CSV 合并读时内存峰值**: 全量 ~135 MB,DuckDB 默认 `memory_limit='4GB'`,单 view 流式,不会爆。
4. **不改 shengyi/zhujiang 路径**: `source_kind='xlsx'` 分支 100% 保留原行为,test_zhujiang 仍需通过。
5. **病理多值字段 ETL-2 处理**: 本任务**不在 ETL-1 拆开**,留 `string_split + UNNEST` 给 ETL-2 的 `template_data.py` 规则。如果用户后续要 ETL-1 拆,作为增量任务处理。
