# 珠江 CT 与病理数据 → Parquet ETL-1 实施计划

## 目标

按现有 `etl1` 框架,把 `docs/demodata/珠江的CT与病理数据/CT与病理数据.xlsx`(20.2 万行、HIS 视图 `v_exam_patient_rpt` 的原始 dump)转换为 `data/zhujiang/` 下的 3 张 parquet:`patient.parquet` / `nodule_imaging.parquet` / `pathology_specimen.parquet`,SQL 层按 EXAM_CLASS + 文本关键词做行级过滤,只保留肺结节相关数据。

## 用户确认的关键决策

1. **SQL 层过滤**(在 ETL-1 阶段按 `EXAM_CLASS` + 文本包含肺/结节/CT 等关键词过滤)
2. **只生成有数据的 3 张表**(`patient` / `nodule_imaging` / `pathology_specimen`)
3. **扩展 `SheetSpec` 加 `where` 字段**(最小改动复用现有框架)

## Step 1. 扩展 etl1 框架:SheetSpec / DerivedSpec / DerivedSource 增加 `where` 字段

**文件**: `backend/app/plugin/module_medical/hospital/etl1/config.py`

- `SheetSpec` 新增 `where: str | None = None`,描述可选的 SQL WHERE 表达式
- `DerivedSpec` 透传 `where`(整段 UNION 后过滤)
- `DerivedSource` 透传(每个 source 可独立设 `where`)
- 加字段验证器 `where_clause_safe()`:禁止分号(`;`)、禁止 `--` 注释、禁止多语句;允许的 token:`AND OR NOT IN LIKE ILIKE BETWEEN IS NULL IS NOT NULL` + 比较运算符 + 括号 + Excel 表头列名(此处已知固定,不走参数化绑定)
- docstring 说明安全模型:`where` 是 ETL-1 配置文件写的常量(不是用户 HTTP 输入),trusted source

**文件**: `backend/app/plugin/module_medical/hospital/etl1/core.py`

- `_process_single_sheet` 第 232-239 行的 `COPY (SELECT ...)` SQL,在 `FROM {sv.view_name}` 之后追加 `WHERE {spec.where}`(仅当 `spec.where` 非空)
- `_process_derived` 第 296-308 行,UNION 内每个 SELECT 后追加对应 source 的 `where`(若设);UNION 外层若 `spec.where` 非空则再套一层 WHERE
- 涉及代码评审修复:Issue #1/#5 已修复 view 复用,本次只追加 SQL 片段,不动 view

## Step 2. 新增珠江医院 center config

**新文件**: `backend/app/plugin/module_medical/hospital/etl1/centers/zhujiang.py`

参照 `shengyi.py` 的 helper(`_str` / `_text` / `_date` / `_int`)实现,但**不需要 `_common_keys`**(珠江 xlsx 没有 visit_ordinal 也不做 visit 反查,所有表 `visit_recovery=False`)。

### 2.1 Sheet 名常量

```python
SHEET = "Select v_exam_patient_rpt"
```

### 2.2 `_PATIENT` SheetSpec

- `target_table="patient"`
- `dedup_key=["patient_id"]`
- `where` = `EXAM_CLASS = 'ＣＴ'` (全角 CT 字面量,跟原始 xlsx 一致)
- 列映射:
  - `PAT_LOCAL_ID` → `patient_id`(required)
  - `SEX` → `gender`
  - (NAME、AGE、SICK_ID、EXAM_DATE、EXAM_NO、EXAM_CLASS、DESCRIPTION、IMPRESSION 全部丢弃 — patient 表只关心身份字段)
- 说明:`first_nodule_date` 需要从 CT 行派生,见 Step 2.5 DerivedSpec

### 2.3 `_NODULE_IMAGING` SheetSpec

- `target_table="nodule_imaging"`
- `dedup_key=["exam_id"]`(EXAM_NO 重复 192 条)
- `where` = `EXAM_CLASS = 'ＣＴ' AND (IMPRESSION ILIKE '%肺%' OR IMPRESSION ILIKE '%结节%' OR DESCRIPTION ILIKE '%肺%' OR DESCRIPTION ILIKE '%结节%' OR DESCRIPTION ILIKE '%胸部CT%')`
- 列映射:
  - `PAT_LOCAL_ID` → `patient_id`(required)
  - `EXAM_NO` → `exam_id`(required)
  - `EXAM_DATE` → `exam_date`(type=date)
  - `EXAM_CLASS` → `exam_type='CT'` 常量注入
  - `DESCRIPTION` → `findings`(type=text, transform=normalize_newlines)
  - `IMPRESSION` → `impression`(type=text, transform=normalize_newlines)
  - `nodule_no` / `nodule_location` / `long_diameter` / `density_type` → 全部 NULL(xlsx 无结构化结节字段)
- 注:`visit_id`/`visit_ordinal` 不生成,`visit_recovery=False`

### 2.4 `_PATHOLOGY_SPECIMEN` SheetSpec

- `target_table="pathology_specimen"`
- `dedup_key=["specimen_id"]`
- `where` = `EXAM_CLASS = '病理' AND (IMPRESSION ILIKE '%肺%' OR IMPRESSION ILIKE '%结节%' OR IMPRESSION ILIKE '%肺癌%' OR IMPRESSION ILIKE '%NSCC%' OR IMPRESSION ILIKE '%腺癌%' OR IMPRESSION ILIKE '%鳞癌%' OR IMPRESSION ILIKE '%小细胞%' OR DESCRIPTION ILIKE '%肺%')`
- 列映射:
  - `PAT_LOCAL_ID` → `patient_id`(required)
  - `EXAM_NO` → `specimen_id`(required,字段重命名)
  - `EXAM_DATE` → `exam_date`(type=date)
  - `IMPRESSION` → `pathology_diagnosis`(type=text, transform=normalize_newlines)
  - `DESCRIPTION` → `exam_detail`(作为 JSON 字符串存放,见说明)
  - `specimen_type` / `sampling_site` / `histology_class` / `tumor_total_size_mm` → 全部 NULL
- 关于 `exam_detail`:JSON 字段,此处原始 xlsx 给的是 DESCRIPTION 文本,直接 `cast(... AS JSON)` 会失败。**方案**:用 `exam_detail_raw text` 替代,把 DESCRIPTION 整段文本存为 string(后续 ETL-2 解析);**或** 用 Python UDF 包成 `{"raw_text": "..."}` JSON。选后者(`to_json_wrapper` transform 注册到 `transforms.py`),保持 `unified_table_schema.md` 中 `pathology_specimen.exam_detail` JSON 语义。

### 2.5 `patient` 的 first_nodule_date 派生

`patient` 表要求 `first_nodule_date`,但 `_PATIENT` 单 sheet 无法在同一 row 内做 `MIN(EXAM_DATE) GROUP BY PAT_LOCAL_ID`。

**方案**:用 `DerivedSpec`,source A = 过滤后的 CT 行(含 patient_id / exam_date),用窗口函数 `MIN(exam_date) OVER (PARTITION BY patient_id)` 注入 `first_nodule_date`;source B 不需要 — 改用 **DerivedSpec 但只用 1 个 source**,在 SELECT 列表里用窗口函数 + DISTINCT。

具体 SQL(在 `_process_derived` 拼出的 `SELECT ... FROM view` 上加 `MIN(exam_date) OVER (PARTITION BY patient_id) AS first_nodule_date`,外层 DISTINCT patient_id):

```sql
SELECT DISTINCT
  patient_id,
  gender,
  MIN(exam_date) OVER (PARTITION BY patient_id) AS first_nodule_date
FROM <view>
WHERE EXAM_CLASS = 'ＣＴ'
```

但 DerivedSpec 当前每个 source 都是 SheetSpec,无法直接加 SELECT-level window 表达式。

**替代方案**(更简单):
- 把 `_PATIENT` 改为 DerivedSpec,1 个 source = 一份 CT-only 的过滤 view,select 列仅 `patient_id` + `gender` + `exam_date`
- `_PATIENT_DERIVED` 的 DerivedSpec 在 `_process_derived` 内做后处理:对每个 source 的 SELECT 加 `MIN(exam_date) OVER (PARTITION BY patient_id) AS first_nodule_date`,然后外层 `SELECT DISTINCT patient_id, gender, first_nodule_date`

**实际操作**:在 `core.py` 的 `_process_derived` 增加一个开关 `with_window_first_nodule: bool = False` 仅用于 patient 派生场景,或更通用 — 加 DerivedSpec 字段 `post_select_window: str | None = None`,在 UNION 外层 SELECT 列表中追加窗口表达式。

**最终决定**(简单优先):**不在 patient 上做 first_nodule_date 派生,本次 patient 表只填 patient_id / gender / source_center='珠江'**,first_nodule_date 留 NULL,在 Step 3 落地后用一条 duckdb SQL 二次脚本在 `data/zhujiang/patient.parquet` 上 UPDATE — 简单透明,与 etl1 框架解耦。

## 风险 & 缓解

| 风险 | 缓解 |
|---|---|
| EXAM_CLASS 全角 `ＣＴ` 在 SQL 字面量中需正确编码 | 直接 `EXAM_CLASS = 'ＣＴ'`,Python 源码文件 # -*- coding: utf-8 -*-,已在;测过类型比对即可 |
| `where` 字段引入 SQL 注入风险 | 仅配置文件使用(不是 HTTP 输入);白名单验证禁止 `;` / `--`;单元测试断言恶意 WHERE 被拒 |
| DESCRIPTION → JSON cast 失败 | 用 transform `to_json_wrapper` 把字符串包成 `{"raw_text": "..."}` JSON |
| 192 条 EXAM_NO 重复,导致 dedup 后行数低于原表 | dedup_key=["exam_id"] / dedup_key=["specimen_id"],由框架 `SELECT DISTINCT` 处理 |
| 后处理脚本与 etl1 框架版本脱钩 | 脚本独立路径,后续若有框架级 first_nodule_date 派生能力再合并 |
