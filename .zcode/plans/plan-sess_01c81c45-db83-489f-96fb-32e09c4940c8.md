## 2. 配置 schema（core/config.py）

用 pydantic 模型定义（与项目其它配置一致），每个医院一份 `CenterConfig`：

```python
class SheetSpec(BaseModel):
    sheet_name: str                      # Excel 工作表名，如 "非隐私信息.就诊.病程记录文档"
    target_table: str                    # parquet 文件名（无扩展名），如 "progress_note"
    header_row: int = 1                  # 表头所在行（默认 1，已修正）
    skip_rows: int = 0                   # 表头之后跳过的行数
    columns: list[ColumnSpec]            # 列级映射
    dedup_key: list[str] | None = None   # 去重键（None 表示不去重）
    visit_recovery: bool = False         # 是否需要 visit_ordinal → visit_id 反查

class ColumnSpec(BaseModel):
    src: str                             # Excel 表头全路径（如 "非隐私信息.就诊.病程记录文档.文档内容"），匹配时 .strip()
    tgt: str                             # 目标 parquet 列名（snake_case 英文）
    type: Literal["string","date","timestamp","int","decimal","bool","text","json"]
    required: bool = False
    default: Any = None
    transform: str | None = None         # transforms.py 里注册的函数 key（如 "normalize_newlines"）

class CenterConfig(BaseModel):
    code: str                            # "shengyi"
    display_name: str
    source_kind: Literal["xlsx","csv"]
    universal_tables: list[SheetSpec]    # 4 张统一表
    hospital_tables: list[SheetSpec]     # 该院独有表
    derived_tables: list[DerivedSpec]    # 跨 sheet 合并/展平（diagnosis 2→1 / surgery 2→1 / anesthesia 2→1 / surgery_front_page 数组展平）
    output_dir: str = "data/{code}"      # 相对仓库根
```

`DerivedSpec` 描述多 sheet 合并（如 diagnosis 合并 sheet4 + sheet6，靠 `diagnosis_source` 区分；anesthesia 合并 sheet8 + sheet9，靠 `event_kind` 区分；surgery_record 把住院病案首页的 `surgeries[]` JSON 数组展平为多行）。

## 3. core.py 引擎（核心循环）

```python
def run_etl1(center: CenterConfig, xlsx_path: Path, out_dir: Path,
             on_sheet_done=None, dry_run=False) -> dict[str,int]:
    con = duckdb.connect(":memory:")
    con.execute("INSTALL excel; LOAD excel;")          # 见 §4
    stats = {}
    # 阶段 1: 单 sheet 直接转换 → parquet
    for spec in center.universal_tables + center.hospital_tables:
        rows = _read_sheet(con, xlsx_path, spec)        # 见 excel_reader.py
        df = _apply_transforms(rows, spec)
        if spec.dedup_key: df = _dedup(df, spec.dedup_key)
        _write_parquet(df, out_dir / f"{spec.target_table}.parquet")
        stats[spec.target_table] = len(df)
        on_table_done and on_table_done(spec.target_table, len(df))
    # 阶段 2: 跨 sheet 合并（diagnosis / surgery / anesthesia）
    for d in center.derived_tables:
        ...
    # 阶段 3: visit_id 反查（见 §5）——在所有 visit_record + 业务表都已落 parquet 后
    _resolve_visits(con, out_dir, center)
    # 阶段 4: manifest
    _write_manifest(center, xlsx_path, out_dir, stats)
    return stats
```

**安全**：复刻 `etl_engine.py:33-34, 95-105` 的 `_SRC_TABLE_RE` 白名单 + path-traversal 校验（对 `target_table` 名做相同校验，确保 parquet 文件名落在 `out_dir` 内）。

## 4. excel_reader.py（duckdb excel 扩展封装）

```python
def read_sheet(con, xlsx_path: Path, sheet_name: str) -> duckdb.DuckDBPyRelation:
    # duckdb excel 扩展语法:
    # SELECT * FROM st_read('path.xlsx', worksheet='Sheet1')
    # 因为所有 cell 都是 inline string, 强制全列 VARCHAR:
    return con.execute(f"""
        SELECT * FROM st_read(?, worksheet=?, all_varchar=true)
    """, [xlsx_path.as_posix(), sheet_name])
```

**实施第一步必须验证的 4 件事**（用户给的 https://duckdb.org/docs/current/core_extensions/excel）：
1. `INSTALL excel; LOAD excel;` 能否在 dev 环境装上（网络可达 community extensions）
2. 200MB xlsx + 26 sheet + 893MB 最大 sheet XML，`st_read` 是否能流式读取而不 OOM
3. `all_varchar=true` 参数是否被 excel 扩展支持（若不支持，回退到 `SELECT CAST(* AS VARCHAR)`，或注册 Python UDF）
4. 中文 sheet 名（`非隐私信息.就诊.病程记录文档`，**含点号**）是否能作为 `worksheet` 参数传入

**降级路径**：若 excel 扩展在 4 项任一失败，回退到 `analyze_xlsx_raw.py` 的 zip + ElementTree.iterparse 流式读取，把行批量 `INSERT INTO` duckdb 临时表再 `COPY TO ... (FORMAT PARQUET)`。降级路径写进 `excel_reader.py` 的 `read_sheet_with_fallback()` 函数，让 core 不感知。

## 5. visit_resolver.py（跨表反查）

**关键事实**：现有 ETL-2 `etl_engine.py` 按 `src_table` 独立处理，**没有 cross-table 能力**，所以 `visit_id` 反查必须在 ETL-1 完成。

```python
def resolve_visits(con, out_dir, center):
    # 1. 读已写好的 visit_record.parquet，建 (patient_id, m) → visit_id 字典
    con.execute("""
        CREATE TEMP TABLE visit_dict AS
        SELECT patient_id,
               CAST(SPLIT_PART(visit_ordinal, '/', 1) AS INTEGER) AS m,
               visit_id
        FROM read_parquet('{out_dir}/visit_record.parquet')
    """.format(out_dir=out_dir))
    # 2. 对每张需要反查的表（visit_recovery=True），LEFT JOIN 回填 visit_id，覆盖写 parquet
    for tbl in NEEDS_RECOVERY:   # medical_history, progress_note, icu_observation, anesthesia_event, diagnosis
        con.execute(f"""
            COPY (
              SELECT t.*, d.visit_id
              FROM read_parquet('{out_dir}/{tbl}.parquet') t
              LEFT JOIN visit_dict d
                ON t.patient_id = d.patient_id
               AND CAST(SPLIT_PART(t.visit_ordinal, '/', 1) AS INTEGER) = d.m
            ) TO '{out_dir}/{tbl}.parquet' (FORMAT PARQUET, OVERWRITE_OR_IGNORE)
        """)
```

注意 schema 文档原文：反查不到时 `visit_id` 置 null，但 `visit_ordinal` 与 `patient_id` 保留 —— LEFT JOIN 自然实现这个语义。

## 6. transforms.py（注册式清洗函数）

```python
TRANSFORMS = {
    "normalize_newlines": lambda s: re.sub(r"\r\n?", "\n", s) if isinstance(s,str) else s,
    "parse_date":         lambda s: _try_parse_date(s),  # 支持 "YYYY-MM-DD[ HH:MM:SS]"
    "parse_timestamp":    lambda s: _try_parse_ts(s),
    "to_int":             lambda s: int(s) if s and s not in ("", "null") else None,
    "to_decimal":         lambda s: Decimal(s) if s else None,
    "to_bool":            lambda s: {"是":True,"否":False,"true":True,"false":False}.get(s, None),
    "json_load":          lambda s: json.loads(s) if isinstance(s,str) else s,
}
```

日期解析用 duckdb 内置 `try_strptime`（比 Python UDF 快），文本规范化用 Python（因涉及 `\r\n` 正则）。

## 7. center config 样本（centers/shengyi.py）

Python 常量风格（与 `template_data.py` 一致），用 `_rename`/`_constant` 辅助函数批量生成 `SheetSpec`。**核心约定**：

- `target_table` 用 schema 文档的英文表名（`patient`/`visit_record`/`diagnosis`/...），与 ETL-2 `MappingRuleModel.src_table` 对齐
- `src` 列用 Excel 表头全路径（如 `非隐私信息.就诊.住院病案首页.诊断.诊断编码`），匹配时 `.strip()`（探索发现 sheet2 有尾随空格）
- `tgt` 列名严格用 `unified_table_schema.md` 里定义的 snake_case 英文（`patient_id`/`visit_id`/`visit_ordinal`/`diagnosis_code`/...）
- `DerivedSpec` 定义 3 个合并：`diagnosis`（sheet4 front_page + sheet6 visit）、`surgery_record`（sheet3 病案首页 + sheet7 手术信息 + 数组展平）、`anesthesia_event`（sheet8 medication + sheet9 observation）
- 7 个空 sheet（sheet12 门诊药物处方 + sheet21-26 基因检测）的 `target_table` 仍登记，但产出 0 行 parquet，保留 schema 兼容性

## 8. service.py + controller（FastAPI 后台任务）

**完全仿照 `etl_service.py` 模式**：
- `Etl1Service.start_import(hospital_id, xlsx_path)` → `asyncio.create_task(_run_etl1_background(...))`
- Redis 进度 key：`etl1:status:{hospital_id}`，TTL 1h，结构 `{stage, current_sheet, sheets_done, sheets_total, error}`
- 通过 `HospitalModel.data_dir` 决定输出目录（与 ETL-2 复用同一个 `data_dir` 字段）
- 完成后更新 `HospitalModel.last_import_time` / `last_import_rows`
- **触发条件**：仅当 hospital 已 `registered`（未配置映射也能跑 ETL-1，因为 ETL-1 产出的是 schema 化 parquet，不依赖 mapping rule）

**Controller endpoint**（加到现有 `hospital/controller.py`）：
- `POST /api/v1/hospital/{id}/etl1/run` —— body `{xlsx_path}` 或 `multipart/form-data` 上传文件
- `GET  /api/v1/hospital/{id}/etl1/status` —— 读 Redis 进度

## 11. 关键修正与坑防御

- **表头修正**：原以为 2 行表头，实际 1 行（`analyze_xlsx_raw.py` 的 `header_rows=10` 是误报，因为所有 cell 都是 inline string 让"全字符串行"判定永远通过）。`SheetSpec.header_row` 默认 1，`skip_rows` 默认 0。
- **行数修正**：`analyze_xlsx_results.json` 里 `data_rows` 比实际少 9 行（因 header_rows 误算）。本次以 `row_count - 1` 为准。
- **中文 sheet 名含点号**：`非隐私信息.就诊.病程记录文档` 这种 sheet 名在 duckdb `worksheet` 参数里要确认转义。若 excel 扩展不接受，降级路径用 zip 内 `xl/worksheets/sheetN.xml` 索引。
- **parquet 文件名必须 snake_case 标识符**：因 ETL-2 `_SRC_TABLE_RE = ^[A-Za-z_][A-Za-z0-9_]*$`。`target_table` 在 config.py 校验。
- **path traversal**：`target_table` 走和 ETL-2 一样的白名单 + resolved path 必须在 `out_dir` 内。
- **空 sheet 处理**：7 个 header-only sheet（门诊药物处方 + 6 个基因检测子类）仍登记 spec，产出 0 行 parquet，保证 ETL-2 端不缺表。
- **资源**：~3.26M 行，最大 sheet 1.05M 行。必须流式读 + 分批写。`st_read` 配合 duckdb 的向量化执行通常没问题，但加一层 `PRAGMA memory_limit='4GB'` 防御。
- **PHI 处理**：ETL-1 阶段**不做脱敏**（只做类型转换 + 列重命名 + 长文本规范化）。脱敏在 ETL-2 之后由 `0006-anonymized-schema-patch-visit.sql` 流水线承担。`nurse_signature` 等字段在 ETL-1 阶段保留（schema 文档列为可选），ETL-2 之后脱敏时再剔除。
