# ETL-2 实施计划：data/*.parquet → 脱敏 → lnrs_anon_* (PostgreSQL)

## 决策摘要（已与用户确认）
- **目标 schema**：ADR-0006 全量 `lnrs_anon_*` 匿名窄表，权威 DDL = `docs/adr/0006-anonymized-schema-lnrs.sql`（schema-qualified、双 ID 体系、软删除）
- **自由文本 PHI**：本轮不清洗，原样入库，`clean_method='regex_only'`、`review_status='pending'` 占位
- **缺失表**：仅处理 data/ 实际存在的 parquet（shengyi: patient+visit_record；xinqiao/zhujiang: patient+nodule_imaging+pathology_specimen），surgery_record/genetic_test/ihc_result/follow_up 跳过并打 warning
- **不实现**：DICOM 表（`anon_dicom_*`）——本轮无 DICOM 源；audit UID map（`lnrs_anon_dicom_uid_map`）按 ADR 物理隔离不建
- **技术栈**：复用现有 duckdb 读 parquet + SQLAlchemy 2.0 async + asyncpg + 现有本地 PG16 容器（docker/lnrs-dev.yaml，user=lnrs/pwd=lnrs_pwd/db=postgres）

## 一、数据处理映射设计（核心）

### 来源 → 落表
| 来源 parquet | → lnrs_anon_* 落点 |
|---|---|
| `{center}/patient.parquet` | 每行 → 1 `anon_patient` 行 |
| `{center}/nodule_imaging.parquet`（仅 xinqiao/zhujiang） | 每行 → 1 `anon_exam`(exam_type='CT') + 1 `anon_report_text`(body_clean=impression+findings) |
| `{center}/pathology_specimen.parquet`（仅 xinqiao/zhujiang） | 每行 → 1 `anon_exam`(exam_type='Pathology') + 1 `anon_report_text`(body_clean=pathology_diagnosis) |
| `{center}/visit_record.parquet`（仅 shengyi） | 本轮**跳过**——ADR-0006 visit 桥(patch-visit.sql)未要求实现，visit_record 无对应 anon 表，仅打 info 日志 |

> 取舍：nodule_imaging 与 pathology_specimen 都按"一次检查"语义落 `anon_exam`，前者 `exam_type='CT'`，后者 `exam_type='Pathology'`。`source_exam_hash = sha256(center + ':' + exam_id)` / `sha256(center + ':' + specimen_id)`。

### 脱敏规则（ADR-0001）
| 字段 | 处理 |
|---|---|
| `patient_id`（明文院内号） | → `anon_id = "ANON_" + HMAC-SHA256(secret, center + patient_id)[:12]`；同时分配 `patient_id = "PT_" + LPAD(nextval(lnrs_anon_patient_seq), 8, '0')` |
| `exam_id` / `specimen_id` | → `anon_exam_id = "ANON_EXAM_" + HMAC-SHA256(secret, center + exam_id)[:12]` |
| `gender` (男/女/女性/男性) | → `sex` ENUM('M','F','U')，'男'→M '女'→F null/未知→U |
| `birth_date` (shengyi) | → `birth_year = year(birth_date)` |
| `birth_year`（珠江-新桥原数据无，置 null） | null |
| `exam_date` | 原值保留 |
| `first_nodule_date` | 本轮不入 anon schema（属于业务字段，patch-visit 才处理），忽略 |
| 报告正文 (impression/findings/pathology_diagnosis) | **原样**入 `body_clean`，`clean_method='regex_only'`，`pii_replaced_count=0`，`review_status='pending'` |
| 多值逗号串（xinqiao pathology 的 gross_findings 等） | 原样拼接进 `body_clean`（本轮不拆分） |

### 幂等 / 软删除（ADR-0006 Rev 2026-07-19）
- `anon_patient`：按 `(center_code, anon_id)` 查找；**活行**→复用 `patient_id`（仅 update last_seen_batch_id）；**软删行**→复活（清空 deleted_*）；**不存在**→`nextval` 发号 + insert
- `anon_exam`：`UNIQUE(center_code, source_exam_hash)` + `ON CONFLICT DO UPDATE last_seen_batch_id`
- `anon_report_text`：PK=anon_exam_id，`ON CONFLICT DO UPDATE body_clean`
- 每张表写 `phi_audit`：`strategy='hmac'`（ID 类）、`'clear'`（birth 月日）、`'llm_replace'`（正文，但 confidence=0 表示未清洗）

## 二、新增/修改文件清单

### 1. 配置（密钥与连接）
- **改** `backend/env/.env.dev`（本地）：`DATABASE_TYPE=postgres`、`DATABASE_PORT=5432`、`DATABASE_USER=lnrs`、`DATABASE_PASSWORD=lnrs_pwd`、`DATABASE_NAME=postgres`
- **改** `backend/env/.env.dev.example`：把注释里的 PostgreSQL 用法提到前面，新增 `LNRS_ANON_SECRET`、`LNRS_ANON_SECRET_VERSION`（占位，值由用户填）
- **改** `backend/app/config/setting.py`：新增 `LNRS_ANON_SECRET: str`、`LNRS_ANON_SECRET_VERSION: str = "v1"` 字段（pydantic-settings 自动读 env）

### 2. 建库
- **新** `backend/sql/0006-anonymized-schema-lnrs.sql`：把 `docs/adr/0006-anonymized-schema-lnrs.sql` 复制到执行目录（保持单一真相源；docs 版本是设计稿，sql/ 是可执行版）
- 不用 alembic（现有 alembic versions 目录是空的且 gitignore；本表与 med_* 解耦，直接用 BEGIN/COMMIT 包裹的原始 DDL 更稳）

### 3. ORM 模型（新建模块）
- **新** `backend/app/plugin/module_medical/hospital/anon_model.py`：定义 7 个 SQLAlchemy 2.0 ORM 类（`__table_args__={'schema':'lnrs'}`），与 DDL 对齐：
  - `AnonIngestBatchModel` / `AnonPatientModel`（双 ID + 软删）/ `AnonExamModel` / `AnonReportTextModel` / `AnonExamFindingModel` / `AnonPhiAuditModel`
  - PG ENUM 用 `sqlalchemy.dialects.postgresql.ENUM`，名字对齐 `lnrs_anon_sex_enum` 等
  - 复用 `app.core.base_model` 的 `ModelMixin`（id/created_at/status...）需谨慎——anon 表自带 `created_at`，**不继承 ModelMixin**，独立定义所有列，避免 id 冲突
  - 导出 `ANON_TABLE_MODELS: dict[str, type]`

### 4. 脱敏核心模块（新建）
- **新** `backend/app/plugin/module_medical/hospital/anonymize.py`：
  - `compute_anon_id(center, patient_id, secret)` → `"ANON_" + hmac.new(secret, f"{center}:{patient_id}".encode(), sha256).hexdigest()[:12]`
  - `compute_anon_exam_id(center, exam_no, secret)` → `"ANON_EXAM_" + ...[:12]`
  - `key_fingerprint(secret)` → sha256(secret)[:16]
  - `schema_hash()` → 对 `0006-anonymized-schema-lnrs.sql` 内容的 sha256（启动时算一次，缓存）
  - `normalize_sex(raw)` → 'M'/'F'/'U'
  - `birth_year_from(birth_date_or_year)` → int|None
  - 常量：`SECRET_VERSION`、`CLEAN_METHOD='regex_only'`、`LLM_MODEL=None`

### 5. ETL-2 引擎（新建，不复用 etl_engine.py——目标表不同、规则不同）
- **新** `backend/app/plugin/module_medical/hospital/anon_etl_engine.py`：
  - `async def import_center(db, center_code, data_dir, batch_id, on_progress)`：主入口，按固定顺序处理 patient → nodule_imaging → pathology_specimen；visit_record 跳过记日志
  - 内部辅助：
    - `_read_parquet(path)`：复用 duckdb 独立连接模式（仿 etl_engine._read_parquet_rows 的安全校验）
    - `_upsert_patient(db, center, anon_id, batch_id, sex, birth_year) -> patient_id`：实现"活→复用/软删→复活/新→发号"三态机
    - `_upsert_exam(db, anon_exam_id, patient_id, center, exam_type, exam_date, source_hash, batch_id)`
    - `_write_report_text(db, anon_exam_id, body, batch_id)`
    - `_write_phi_audit(db, batch_id, table, field, raw_value, strategy, confidence)`
  - 用 `postgresql.insert(...).on_conflict_do_update(...)` 实现幂等
  - `patient_id` 发号：`SELECT nextval('lnrs.lnrs_anon_patient_seq')` 然后 LPAD——放单条 SQL，避免并发问题（ETL 单批单线程）
  - 批量 INSERT 用 `BATCH_SIZE=500`（与 etl_engine 一致）

### 6. 编排层（新建）
- **新** `backend/app/plugin/module_medical/hospital/anon_etl_service.py`：
  - `async def run_anon_etl(centers=None)`：遍历 `data/{center}/`，每中心：开 batch → 调 `import_center` → 关 batch（status=success/failed，row_counts JSON）
  - 创建 `lnrs_anon_ingest_batch` 行（batch_id=uuid4, source_kind='csv_report', source_locator=data_dir, source_sha256 读 manifest.json, secret_version/key_fingerprint/schema_hash 自动填）
  - 进度可选写 Redis key `anon_etl:status:{center}`（复用 etl_service 的模式，但本轮简化为日志即可，不强依赖 Redis）

### 7. CLI 入口（新建，方便独立跑）
- **新** `backend/app/plugin/module_medical/hospital/anon_etl/__main__.py`（或直接在 anon_etl_engine 同级加 `if __name__`）：
  - `python -m app.plugin.module_medical.hospital.anon_etl --centers shengyi,xinqiao,zhujiang --data-root ../../data`
  - 参数：`--centers`（默认全部）、`--data-root`（默认 `<repo>/data`）、`--dry-run`
  - 走同步 `asyncio.run(run_anon_etl(...))`，用 `async_db_session()`

### 8. 单元测试

  - center 前缀参与（跨中心同 patient_id 不碰撞）
  - 截断长度 12 hex
  - sex 归一化各分支
  - birth_year 从 date / int / null 的转换

## 五、风险与边界
- **visit_record（131k 行 shengyi 就诊数据）本轮不入库**——ADR-0006 的 visit 桥(patch-visit.sql)未启用，用户已同意跳过。会在日志和服务返回里显式提示。
- **自由文本未清洗**——`review_status='pending'` 等待后续 regex+LLM 迭代，body_clean 暂含明文 PHI 风险（用户已知情同意）。
- **多值字段（xinqiao pathology 的逗号串）**原样进 body_clean，不做 finding 拆分（避免引入解析复杂度，finding 表本轮为空）。
- **DICOM 表不建**（无源）。
- **密钥**：首轮用 setting.py 读取的 `LNRS_ANON_SECRET`，建议用户生产用环境变量注入；key_fingerprint 落 batch 表用于轮换追溯。
- **patient_seq 并发**：ETL 单批单线程顺序 nextval，无并发风险；未来若多中心并行导入需改成 `INSERT ... RETURNING` 批量。
