# 敏感环境变量与配置项审计

> **关于占位符**：本文档原本逐字记录了若干已泄漏的凭据（GitLab PAT、PostgreSQL 超管/应用口令、
> 生产服务器 IP、JWT/HMAC 默认密钥、docker 默认口令、`run-h42.sh` 个人路径等）。
> 入库前已统一替换为 `<GITLAB_PAT>` / `<SUPER_PWD>` / `<APP_PWD_H42>` / `<APP_PWD_H125>` /
> `<DB_HOST_H42>` / `<DB_HOST_H125>` / `<DEFAULT_SECRET_KEY>` / `<DEFAULT_LNRS_ANON_SECRET>` /
> `<MYSQL_ROOT_PASSWORD>` / `<MYSQL_PASSWORD>` / `<REDIS_PASSWORD>` /
> `<VITE_LOCK_ENCRYPT_KEY>` / `<REPO_ROOT>` / `<PY_BIN>` 等占位符。
> 真实值仅保留在原仓库历史与本地审计草稿中；如需对照，请使用 `git log -p -- <file>` 调取历史。

## 概览

本项目采用 `pydantic-settings` + `backend/env/.env.<ENV>` 的注入模式，集中配置在 `backend/app/config/setting.py`；前端通过 Vite 注入 `VITE_*`，定义在 `frontend/web/.env*`。本次审计发现：

- **2 处已泄漏到 Git 的凭据**（GitLab PAT + PostgreSQL 超管密码），**必须视为已泄漏**并立即处理。
- **6 个真实 `.env*` 配置文件已被 Git 跟踪**，且 `.gitignore` 未生效。
- **`setting.py` 中 2 个默认密钥**（JWT 与 HMAC）一旦部署未覆盖即等于公开。

---

## 高度敏感（必须立刻处理，泄露后无法撤销）

### 1. Git remote `hermes` 中嵌入了 GitLab Personal Access Token
- 位置：`.git/config`
- 值：`http://<GITLAB_PAT>@hermes2026git.nmdi.cn/lnrs/lnrs_web.git`（已脱敏，原值前缀为 `glpat-`）
- 风险：`glpat-*` 是 GitLab PAT 标准前缀，可访问整个 GitLab 项目的 read/write，甚至 api scope。一旦 `.git/config` 被打包/分享，所有能拿到仓库的人都能直接读写 hermes 远程仓库。
- 修复：立刻在 GitLab 后台吊销该 PAT 并重新签发；改用 SSH 或 PAT 存放在系统凭据管理器；清理 `.git` pack 文件中可能残留的 URL。

### 2. `deploy-ci.sh` 中硬编码 GitLab PAT（HTTP `PRIVATE-TOKEN` header）
- 位置：`deploy-ci.sh:23`
- 值：`git -c http.extraHeader="PRIVATE-TOKEN: <GITLAB_PAT>" fetch origin`（已脱敏）
- 风险：与远程 URL 中的 PAT 是同一个 token，已被 `git ls-files` 列入跟踪文件。
- 修复：撤销并重发 PAT；改为从环境变量/CI 变量注入（`${GITLAB_TOKEN}`）。

### 3. `scripts/migrate_dev_to_h42.sh` 硬编码 PostgreSQL 超管密码 + 内网 IP
- 位置：`scripts/migrate_dev_to_h42.sh:16-20`
- 值（已脱敏）：
  ```
  H42_HOST=<DB_HOST_H42>
  SUPER_PWD=<SUPER_PWD>
  APP_USER=lnrs
  APP_PWD=<APP_PWD>
  ```
- 风险：`<SUPER_PWD>` 是 PostgreSQL `postgres` 超级用户口令；`<DB_HOST_H42>` 是内网目标主机；脚本已被 Git 跟踪。
- 修复：立即在 `<DB_HOST_H42>` 上修改 `postgres` 用户密码；脚本改为从环境变量/`.pgpass` 注入；`H42_HOST` 用参数传入。

### 4. `backend/env/.env.h125` 已入库的生产环境密码与服务器地址
- 位置：`backend/env/.env.h125`
- 值（已脱敏）：`DATABASE_PASSWORD = "<APP_PWD_H125>"`，注释标注 `<DB_HOST_H125>`
- 风险：已入库的环境文件含生产服务器的明文密码；暴露生产服务器 IP。
- 修复：立刻在 `<DB_HOST_H125>` 上修改数据库密码；`git rm --cached` 并改用 `.env.h125.example` 模板。

### 5. `backend/env/.env.h42` 已入库的内网数据库地址 + 密码 + ETL HMAC 密钥
- 位置：`backend/env/.env.h42`
- 值（已脱敏）：
  ```
  DATABASE_HOST = "<DB_HOST_H42>"
  DATABASE_PASSWORD = "<APP_PWD_H42>"
  LNRS_ANON_SECRET = "<DEFAULT_LNRS_ANON_SECRET>"
  ```
- 风险：暴露内网 DB 与口令；ETL 脱敏 HMAC 密钥默认值为仓库明文，若未覆盖则可被反向还原 `anon_id / anon_exam_id`。
- 修复：修改 `lnrs` 数据库密码；`LNRS_ANON_SECRET` 改为必填；`git rm --cached` 并清理历史。

## 中度敏感（凭据形态存在，需结合上下文判断）

### 6. `docker/.env` 入库且含 MySQL/Redis 默认凭据
- 位置：`docker/.env`
- 值（已脱敏）：
  ```
  MYSQL_ROOT_PASSWORD=<MYSQL_ROOT_PASSWORD>
  MYSQL_PASSWORD=<MYSQL_PASSWORD>
  REDIS_PASSWORD=<REDIS_PASSWORD>
  ```
- 风险：弱口令、公开项目（fastapiadmin 默认用户名/密码广为人知）。`docker/.env` 应被 `.gitignore` 忽略但当前未生效。
- 修复：`git rm --cached docker/.env`；`docker/.env.example` 已存在；强制密码策略 ≥ 20 位随机。

### 7. `frontend/web/.env` 入库，锁屏加密密钥泄漏
- 位置：`frontend/web/.env`
- 值（已脱敏）：`VITE_LOCK_ENCRYPT_KEY = <VITE_LOCK_ENCRYPT_KEY>`
- 风险：锁屏密码本地加密的固定密钥；任何拿到此仓库的人都能解密用户本地缓存的"锁屏密码"。`.gitignore` 第 80 行写了 `frontend/web/.env` 但未生效。
- 修复：`git rm --cached frontend/web/.env`；`.env.example` 已存在。

### 8. `frontend/web/.env.development` 与 `.env.production` 入库
- 位置：`frontend/web/.env.development`、`frontend/web/.env.production`
- 值：dev: `VITE_API_BASE_URL = http://127.0.0.1:8610`；prod: `VITE_API_BASE_URL = https://service.fastapiadmin.com`
- 风险：暴露内部网络结构与生产域名。
- 修复：`git rm --cached`，由 CI/CD 在构建阶段注入。

### 9. `setting.py` 中硬编码 `SECRET_KEY` 默认值
- 位置：`backend/app/config/setting.py:67`
- 值（已脱敏）：`SECRET_KEY: str = "<DEFAULT_SECRET_KEY>"`
- 用途：`backend/app/core/security.py`（JWT encode/decode）；`backend/app/core/dependencies.py`
- 风险：HS256 JWT 密钥；只要部署未用 `.env.*` 覆盖，就会沿用仓库默认值，攻击者可伪造任意用户的 token。
- 修复：把默认值改为 `""`，启动时检测为空则抛错。

### 10. `setting.py` 默认 `LNRS_ANON_SECRET = "change-me-in-production-please"`
- 位置：`backend/app/config/setting.py:244`
- 用途：`backend/app/plugin/module_medical/hospital/anonymize.py:69` 用于生成确定性 `anon_id / anon_exam_id` 的 HMAC 密钥。
- 风险：与上文 h42 文件组合，若未覆盖则匿名化结果可预测、可碰撞。
- 修复：删除默认值；启动时强制非空校验。

### 11. `setting.py` 默认 `ALLOW_ORIGINS = ["*"]` + `ALLOW_CREDENTIALS = True`
- 位置：`backend/app/config/setting.py:58-61`
- 风险：跨域任意来源 + 携带凭据。被 `app/core/middlewares/CustomCORSMiddleware` 消费。
- 修复：生产 `.env` 必须把 `CORS_ORIGIN_ENABLE=False` 或显式列 `ALLOW_ORIGINS`，并删除 `*` 默认值。

### 15. `run-h42.sh` 包含本机绝对路径与 conda 环境路径

## 修复优先级建议

1. 立刻撤销 GitLab PAT，修改 PostgreSQL 超管密码（视为已泄漏）。
2. `deploy-ci.sh`、`scripts/migrate_dev_to_h42.sh` 移除硬编码凭据，改为环境变量/CI 变量注入。
3. `backend/env/.env.h125`、`backend/env/.env.h42`、`docker/.env`、`frontend/web/.env*` 依次 `git rm --cached`，落到 `.env.*.example` 模板。
4. `setting.py` 的 `SECRET_KEY`、`LNRS_ANON_SECRET` 默认值改为 `""` 并启动校验。
5. `.gitignore` 增加：`backend/env/.env.*`、`docker/.env`、`frontend/web/.env*`、`*.pem`、`*.key`、`*.pfx`、`*.p12`、`secrets/`、`credentials*`、`*.pdump`、`*.dump`。
6. `docs/database_migration_dev_to_h42.md` 替换为占位符。
7. 远程 URL 用 `git remote remove hermes && git remote add hermes https://hermes2026git.nmdi.cn/lnrs/lnrs_web.git`（推荐 SSH）。
8. 历史清理：使用 `git filter-repo` 或 BFG 对上述敏感文件/凭据逐个清理后 force push。此操作会重写历史，需所有协作者重新克隆。
