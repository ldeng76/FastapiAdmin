# ADR 0002: Schema 映射管理（ETL 规则）

> 状态：已接受
> 日期：2026-07-07

## 背景

统一表 Schema（`docs/unified_table_schema.md`）已定义多中心数据的标准化结构和转换规则。但映射规则目前仅为文档形式——每次新增医院，开发人员需硬编码映射逻辑。需要将映射规则变为系统内可配置、可复用的元数据。

同时需要一个清晰的医院就绪生命周期，将"创建入口"和"数据可用"分离开来。

## 决策

### Schema 映射

- 映射规则粒度：**(源表, 源字段) → (目标表, 目标字段, 转换规则)**
- 映射配置独立于医院注册，可反复编辑
- 系统携带已知医院的映射模板（省医、珠江-新桥），注册时可选模板预填

### 医院就绪生命周期

四阶段顺序流转：

| 阶段 | 含义 | 可执行操作 |
|------|------|-----------|
| 已注册 | 医院入口存在，映射未配置 | 编辑医院信息、配置映射 |
| 映射已配置 | 字段映射规则已确认 | 上传数据、触发 ETL、编辑映射 |
| 数据已导入 | ETL 完成，数据入库但不可查询 | 查看导入报告、上线发布、重新导入 |
| 已上线 | 数据可供查询和建模 | 下线（回到上一阶段）、查看数据 |

不可逆操作需显式确认（如重新导入会覆盖已导入数据）。

## 后果

- 新增第三家医院时，管理员在 UI 配置映射或选模板预填 → 上传数据 → ETL 导入 → 上线。无需研发介入
- ETL 引擎变为通用框架：读取映射配置 → 执行转换 → 写入 PostgreSQL，不再为每家医院硬编码
- 映射配置本身需要版本化管理（映射变更 → 重新导入 → 数据更新）
