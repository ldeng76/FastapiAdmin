# FASTQ 结构化展示功能实现文档

## 1. 功能目标

将输入的 FASTQ 纯文本解析为 **结构化的 Read 记录列表**，并在界面中以表格/卡片形式展示，替代直接显示原始四行文本。要求支持双端识别、序列碱基着色、质量可视化、交互查看与原始文本切换，使测序数据可读、可查、可操作。

## 2. 适用范围

本文档面向全 AI Agent，作为实现以下功能的唯一技术依据：

- 输入：一段符合 FASTQ 格式的文本（字符串或文件内容）。
- 输出：一个可在浏览器中运行的交互式界面，完成以上解析与展示。

## 3. 输入数据格式

FASTQ 格式每条记录固定为 4 行：

```
@READ_ID 描述信息（可选）
SEQUENCE
+
QUALITY_STRING
```

其中：

- 第 1 行以 `@` 开头，随后为 read 的完整标识符。
- 第 2 行为碱基序列，由 A/T/C/G/N 组成。
- 第 3 行以 `+` 开头，可包含与第 1 行相同的标识符（也可省略）。
- 第 4 行为质量字符串，每个字符对应第 2 行每个碱基的 ASCII 编码质量值。

### 示例（取自用户输入）

```
@A00582:907:H7255DSX3:1:1101:8196:1063 1:N:0:TAAGGCGA
GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCCATTTGTTCAACTCACAGTTT
+
FF,FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF
```

注意：示例中质量字符串可能包含逗号等字符，解析时不应假设质量字符串只包含 ASCII 字母。

## 4. 功能需求

### 4.1 解析器

- 按 `\n` 或 `\r\n` 读取文本并逐行处理。
- 每 4 行为一组，若文件末尾不足 4 行则报错并终止。
- 校验规则：
  - 第 1 行必须以 `@` 开头。
  - 第 3 行必须以 `+` 开头。
  - 第 2 行序列长度必须等于第 4 行质量字符串长度。
- 若校验失败，应跳过该完整记录并给出错误提示，但不得中断整个解析过程。

### 4.2 数据结构

解析后每条 read 应生成如下结构化对象（以 JSON 示例）：

```json
{
  "rawHeader": "A00582:907:H7255DSX3:1:1101:8196:1063 1:N:0:TAAGGCGA",
  "sequence": "GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCCATTTGTTCAACTCACAGTTT",
  "qualityString": "FF,FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF",
  "qualityScores": [45, 37, 37, ...],
  "length": 59,
  "pairEnd": 1,
  "pairKey": "A00582:907:H7255DSX3:1:1101:8196:1063"
}
```

字段说明：

- `rawHeader`：第一行的完整内容（去掉开头的 `@`）。
- `sequence`：第二行原始碱基序列。
- `qualityString`：第四行原始质量字符串。
- `qualityScores`：质量字符串转换后的数值数组，每个元素为整数。
- `length`：序列长度，等于 `sequence.length`。
- `pairEnd`：双端标识，取值为 `1`、`2` 或 `0`（未知）。
- `pairKey`：用于双端配对的唯一键。

### 4.3 质量值转换

默认按照 **Sanger Phred+33** 标准：

```
Phred Score = ASCII(qualityChar) - 33
```

质量分数输出范围通常为 0~41，但如果出现负数或大于 93 的值，应保留原始值并标记异常。

### 4.4 双端配对识别

双端测序中，R1 和 R2 记录具有相同的“核心 ID”但 `pairEnd` 不同。

识别规则：

1. 从 `rawHeader` 中提取第一部分（以空格分隔的字段），记为 `headerField`。
2. 检查 `headerField` 中是否包含 `1:N:0:` 或 `2:N:0:` 等模式：
   - 若包含 `1:N:0:`，设 `pairEnd = 1`。
   - 若包含 `2:N:0:`，设 `pairEnd = 2`。
   - 均不包含则 `pairEnd = 0`。
3. `pairKey` 为 `headerField` 去掉 `pairEnd` 前缀后的部分，例如：
   - R1：`A00582:907:H7255DSX3:1:1101:8196:1063`（`rawHeader` 为 `...1063 1:N:0:TAAGGCGA`，去空格后取前段，再去除末尾的 ` 1:N:0:TAAGGCGA` 实际比较复杂）。
 
   **简化实现**：将 `rawHeader` 中 `1:N:0:` 或 `2:N:0:` 替换为统一的占位符（如 `PAIR:`），得到的字符串作为 `pairKey`。示例：
   - R1 rawHeader：`A00582:907:H7255DSX3:1:1101:8196:1063 1:N:0:TAAGGCGA`
   - R2 rawHeader：`A00582:907:H7255DSX3:1:1101:8196:1063 2:N:0:TAAGGCGA`
   - 替换后两者均为：`A00582:907:H7255DSX3:1:1101:8196:1063 PAIR:TAAGGCGA`
   - 该字符串即 `pairKey`，用于匹配。

4. 若两条记录的 `pairKey` 相同且 `pairEnd` 分别为 1 和 2，则判定为同一对双端 reads。

### 4.5 原始视图

界面必须提供“原始文本”视图与“结构化视图”的切换功能。原始视图应使用等宽字体、无自动换行、支持横向滚动，并保持 FASTQ 原始内容不变。

## 5. 界面展示要求

### 5.1 结构化视图

采用 **表格 + 可展开行** 的方式展示：

- 每条 read 默认显示为一行，列包含：
  - 序号
  - Read ID（`rawHeader` 开头到第一个空格的部分）
  - 长度（bp）
  - 平均质量（Q30/Q20 百分比或简单平均分）
  - 双端标记（R1/R2/单端）
  - 序列预览（前 50bp，按碱基着色，超出部分以“...”省略）
  - 质量概览（迷你条形图或热力条）
- 点击行可展开，显示：
  - 完整序列（按碱基着色）
  - 完整质量字符串（可选按质量着色）
  - 每条碱基的质量柱状图或热力图（横向排列）
  - 原始 header 与质量分数列表

### 5.2 碱基着色

使用固定颜色方案（可配置）：

| 碱基 | 颜色 |
|------|------|
| A | 绿色 `#2E8B57` |
| T | 红色 `#DC143C` |
| C | 蓝色 `#1E90FF` |
| G | 橙色 `#FF8C00` |
| N / 其他 | 灰色 `#808080` |

每个碱基应使用 `<span>` 等独立元素包裹，以便交互。

### 5.3 质量可视化

- **每个碱基的质量以背景色渐变呈现**（可选覆盖在序列上方或单独一行）：
  - Q ≥ 30：绿色背景
  - 20 ≤ Q < 30：黄色背景
  - Q < 20：红色背景
- 也可在展开行中显示“质量热力条”，与序列一一对应。
- 必须提供质量值的 tooltip（鼠标悬停到某个碱基时显示具体质量分数）。

### 5.4 双端配对展示

- 若检测到双端配对，界面应自动将 R1 和 R2 在表格中相邻显示，并在行首用相同颜色竖条或括号标记成对。
- 支持按 `pairKey` 分组，允许展开后同时查看 R1 和 R2 的完整序列。

### 5.5 交互功能

- 顶部搜索框：支持按 Read ID、pairKey、序列片段（子串）搜索。
- 排序：可点击表头按长度、平均质量、Read ID 排序。
- 过滤：可按单端/双端类型或质量值范围过滤。
- 分页：每页显示 10/20/50/100 条，或使用虚拟滚动（推荐）。
- 原始视图切换按钮。

### 5.6 空状态与错误处理

- 无数据时显示“未找到匹配的 FASTQ 记录”。
- 解析错误时在界面上方提示错误数量及原因，但仍渲染成功解析的部分。

## 6. 性能要求

- 支持一次性解析并展示至少 **100,000 条** reads 而不崩溃。
- 若使用 DOM 渲染表格，必须使用虚拟滚动（如 `react-window`、`vue-virtual-scroller` 等）仅渲染可见行。
- 解析过程应放在 **Web Worker** 中执行，避免阻塞 UI 线程。
- 序列着色渲染时，建议将每个碱基的 DOM 节点数控制在合理范围内，避免创建过多节点。可使用 Canvas 绘制序列或限制默认预览长度。

## 7. 前端技术要求

- 使用现代前端框架（React、Vue 或纯 JS 皆可），但要具备组件化能力。
- UI 使用等宽字体展示序列，建议 `font-family: "Courier New", Consolas, monospace`。
- 样式可通过 CSS 或 CSS-in-JS 实现，颜色必须与文档约定一致。
- 所有交互（搜索、排序、过滤）应在客户端完成，无需后端。

## 8. 验收标准

1. 给定文档中示例的 FASTQ 文本，能够正确解析出 3 条 record（其中前两条为同一对双端）。
2. 界面显示表格，双端记录相邻出现，且 R1/R2 标识正确。
3. 序列 A/T/C/G 颜色正确。
4. 展开某条 read 后可看到完整序列、质量热力条及具体质量数值。
5. 鼠标悬停到序列碱基位置时，显示该碱基类型与质量分数。
6. 点击“原始视图”按钮，显示原始四行文本，无换行。
7. 在搜索框输入 `A00582` 时能过滤出对应记录。
8. 使用 100,000 条模拟 FASTQ 数据测试时，页面滚动流畅，无卡顿。

## 9. 实现建议

- 推荐架构：
  - `Parser` 模块：负责解析文本、校验、转换质量分数、双端配对识别。
  - `Store` 模块：存储解析后的 record 数组，提供搜索/排序/过滤状态。
  - `UI` 模块：负责表格渲染、展开行、交互事件。
  - `RawViewer` 模块：渲染原始文本。
- 所有模块应具备单元测试，尤其是 Parser 的质量转换与双端识别逻辑。
